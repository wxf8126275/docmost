# 配置 AI 提供方 API 密钥（ai-api-key）

## 问题
AI 对话后端（`apps/server/src/core/ai-chat`）已完整实现并通过单元测试（28 个测试全部通过），
但环境里没有配置任何 AI 提供方凭证，因此无法真正调用大模型。用户希望对话功能能端到端跑通，
并且**复用现有的前端页面**（即已在 `/ai` 接好的 `ee/ai-chat` 页面），不再新建任何 UI。

## 行为
- 后端通过 `EnvironmentService` 从环境变量读取 AI 提供方配置：
  - `OPENAI_API_KEY`（必填）—— 对应 `getOpenAiApiKey()`
  - `OPENAI_API_URL`（选填）—— 对应 `getOpenAiApiUrl()`；用于 OpenAI 兼容端点 / 代理（如 OpenRouter）
  - `AI_CHAT_MODEL`（选填）—— 对应 `getAiChatModel()`；未设置时默认 `gpt-4o-mini`
- 配置好密钥后，`/api/ai/chats` 的流式接口即可真正请求到模型。
- 现有前端页面（`apps/client/src/ee/ai-chat`）原样复用，不新增前端代码。
- 密钥缺失 / 配置错误时，必须向用户给出清晰的错误提示（而不是白屏崩溃）。

## 验收标准
- `OPENAI_API_KEY` 已在后端环境变量中配置（写入 `.env` 或进程环境）
  → 可通过配置存在性检查 / `EnvironmentService.getOpenAiApiKey()` 的单元测试验证。
- LLM 客户端能依据配置好的 key / url / model 组装出提供方模型
  → 可通过单元测试验证（mock `streamText`，断言 model 与 baseURL 来自环境变量）。
- （手动 / demo，需真实密钥）用有效密钥发起对话请求，能通过 `/api/ai/chats` 流式返回，
  并在现有 `/ai` 页面中正常渲染。

## 上下文
- 技术栈：NestJS 后端（`apps/server`）、React/Vite 前端（`apps/client`，`ee` 页面）。
- 关联功能：`ai-chat`（已完成）—— 后端 `core/ai-chat` 与前端路由均已就绪。
- 约束：
  - 复用现有 `ee/ai-chat` 前端页面；不得引入新的 UI。
  - 凭证只放在环境变量中——切勿把密钥提交进源码。
  - `ee` 页面受企业版 `Feature.AI` 许可控制，许可问题由用户自行处理，不在本功能范围内。
- 非目标：
  - 不新建前端 UI。
  - 不新增 `core/ai-chat` 已支持范围之外的模型提供方（仅通过 `OPENAI_API_URL` 兼容 OpenAI 系）。
  - 不涉及 embedding / 向量库的改动。
