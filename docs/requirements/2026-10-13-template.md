# Template Backend (Templates API)

## Problem
前端 `apps/client/src/ee/template` 已完整实现模板模块（列表页 `template-list.tsx`、编辑器 `template-editor.tsx`、各类组件、`template-query.ts` / `template-service.ts` / `template.types.ts`），并通过 `api.post(...)` 调用 6 个后端接口。但服务端仅有数据访问层 `TemplateRepo`（`apps/server/src/database/repos/template/template.repo.ts`）与迁移 `20260412T135891-templates.ts`，**缺失** controller / service / module / DTO，导致所有模板请求 404。需补齐后端接口，使现有前端页面真正可用。

## Behaviors
- 在 `apps/server/src/ee/template/` 下新建 `TemplateModule`，接入 `ee.module.ts`（AppModule 已按条件动态加载，全局前缀 `api` → `/api/templates/*`）。
- 实现 `TemplateController`（`@Controller('templates')`，`@UseGuards(JwtAuthGuard)` + `@AuthUser()` + `@AuthWorkspace()`），覆盖前端 `template-service.ts` 依赖的全部 6 个端点：
  - `POST /api/templates`（列表）→ 返回 `{ items: ITemplate[], meta: { limit, hasNextPage, hasPrevPage, nextCursor, prevCursor } }`
  - `POST /api/templates/info`（按 id 查询，含 `content`）→ `ITemplate`
  - `POST /api/templates/create` → `ITemplate`
  - `POST /api/templates/update` → `ITemplate`
  - `POST /api/templates/delete`（按 `templateId`）→ `void`
  - `POST /api/templates/use`（按 `templateId` + `spaceId` + 可选 `parentPageId`）→ `IPage`（复用 `PageService.create` 从模板 `content` 创建页面）
- 实现 `TemplateService`：list（依赖 `TemplateRepo.findTemplates`，需 `accessibleSpaceIds`，由 `SpaceMemberRepo.getUserSpaceIds(user.id)` 提供）、info（含 content）、create、update、delete、`useTemplate`（取模板 → 调 `PageService.create` 以 `format:'json'` 生成页面，含 ydoc/textContent/position/创建者）。
- 新建 `template.dto.ts`，声明前端下发的全部字段（`ValidationPipe` 为 `whitelist:true`，未声明字段会被剥离）。
- 写操作遵循权限约定：创建/更新/删除模板要求当前用户为 workspace admin 或工作区开启了 `settings.templates.allowMemberTemplates`；`useTemplate` 要求目标 `spaceId` 在用户的 `accessibleSpaceIds` 内（否则 `ForbiddenException`）。

## Acceptance Criteria
- `POST /api/templates` 不再 404，返回结构与前端 `IPagination<ITemplate>` 一致（`meta.hasNextPage` / `meta.nextCursor` 可用于无限滚动）。 → 单元/集成验证
- `POST /api/templates/info` 返回含 `content` 的 `ITemplate`，结构与 `template.types.ts` 一致。 → 单元验证
- `create` / `update` / `delete` 端点在通过后可用；未授权用户（非 admin 且未开启 allowMemberTemplates）被拒绝。 → 单元验证
- `POST /api/templates/use` 生成一个新页面并返回 `IPage`（含 `slugId`/`title`/`spaceId`），其内容与模板一致。 → 集成验证
- `pnpm --filter server test` 相关用例通过。 → test

## Context
- Tech stack: NestJS 11 (Fastify) + Kysely(Postgres)；全局 `ValidationPipe({ whitelist:true, transform:true })` → DTO 必须声明所有前端下发字段。
- 全局路由前缀 `api`；控制器使用 `@UseGuards(JwtAuthGuard)` + `@AuthUser()` + `@AuthWorkspace()`。
- 数据层已就绪：`TemplateRepo` 提供 `findById(includeContent)`、`findTemplates(workspaceId, accessibleSpaceIds, pagination, {spaceId})`、`insertTemplate`、`updateTemplate`、`deleteTemplate`。
- `TemplateRepo.findTemplates` 的 `accessibleSpaceIds` 语义：空数组时仅返回 `spaceId is null` 的全局模板；非空时返回该用户可访问空间内的模板 + 全局模板。
- 实体字段（`templates` 表）：`id, title, description, content(jsonb), ydoc(bytea), icon, spaceId(uuid,nullable), workspaceId, creatorId, lastUpdatedById, collaboratorIds(uuid[]), textContent, tsv, createdAt, updatedAt, deletedAt`。
- `PageService`（由 `PageModule` 导出，可注入）的 `create(userId, workspaceId, dto, trx?, isBase?)` 负责把 `content`（`format:'json'`）转为 ydoc/textContent、计算 position、落库并登记 watcher，可直接复用。
- 前端 `ITemplate` 类型字段：`id, title, description?, content?, icon?, spaceId?, workspaceId, creatorId, lastUpdatedById?, creator?, createdAt, updatedAt`。

## Constraints
- 不修改前端（沿用现有页面、query、service、types）。
- 不改动迁移；复用现有 `templates` 表结构。
- DTO 字段需与前端 `template-service.ts` 实际发送/接收的字段严格对齐，否则白名单校验会剥离数据。
- 遵循 `docs/team/conventions.md`：函数 ≤40 行、文件 ≤400 行、无 `any`、错误显式处理、公共函数有注释说明 WHY。

## Non-goals
- 模板的实时协作 / WS 广播（与 base 模块不同，模板编辑器为只读协作，不要求服务端 WS）。
- 模板 `collaborator_ids` 的完整协作者权限模型（本任务仅处理 creator / 基础访问控制）。
- 模板分类、标签、公开分享等扩展能力。
