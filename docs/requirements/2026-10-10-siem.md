# SIEM 流式转发（SIEM streaming & destinations）

## Problem
工作区「设置 → Audit logs & SIEM」中的 **SIEM 流式转发** 标签页已有完整前端（目的地管理、测试、重试、状态展示），但后端缺少对应的接口与投递实现：目前 `siem_destinations` 表与 `SIEM_QUEUE` 队列基础设施已就绪，却没有 Controller / Service / Repo，也没有把审计日志真正转发到外部 SIEM。结果是前端调用 `POST /siem/*` 全部 404，功能不可用。

目标：沿用现有前端页面，补全后端接口（目的地 CRUD + 测试 + 重试 + 真实流式投递），并在社区/自托管版开放该功能入口（菜单可点击）。

## Behaviors
- 列出工作区的 SIEM 目的地：`POST /siem/destinations`。
- 创建目的地：`POST /siem/destinations/create`（含名称、类型 http/splunk_hec/datadog、config、secrets、enabled；上限 `SIEM_MAX_DESTINATIONS_PER_WORKSPACE=2`）。
- 更新目的地：`POST /siem/destinations/update`（名称、config、secrets、enabled；乐观锁 `version`）。
- 删除目的地：`POST /siem/destinations/delete`。
- 测试目的地连通性：`POST /siem/destinations/test`——向后端实际发一条合成审计事件到目标地址，返回 `{ delivered, statusCode?, error? }`（不落库；若带 `destinationId` 则复用已存密钥）。
- 重试投递：`POST /siem/destinations/retry`——重置 `nextAttemptAt`/`consecutiveFailures` 并触发一次投递扫描。
- 流式投递：审计日志写入后，异步投递到该工作区所有「启用」的目的地；按类型构造报文（http JSON/NDJSON、Splunk HEC、Datadog Logs API），通过 SSRF 安全的 `OutboundAgentFactory` 发送；更新目的地统计（lastDeliveredAt、lastError、consecutiveFailures、status healthy/failing、failingSince、nextAttemptAt、cursor）。

## Acceptance Criteria
- 6 个 `POST /siem/*` 端点全部可用（owner 鉴权），列表/创建/更新/删除/测试/重试返回前端约定结构 → 后端集成测试覆盖。
- 创建/更新时，`secrets` 以加密形式存入 `siem_destinations.secrets`，响应不泄露明文密钥，`hasSecrets` 正确标记 → 单测覆盖。
- 测试接口对给定目的地真实发起 POST 并返回 `delivered/statusCode/error` → 单测用 mock outbound agent 覆盖三种类型。
- 审计日志产生后入队 `SIEM_DELIVER`，处理器将事件投递到启用目的地并更新统计/游标 → 单测（mock 队列 + mock outbound）覆盖。
- `tsc --noEmit` 与既有测试无回归；服务可启动（`SiemModule` 注册到 `EeModule`）。
- 社区/自托管版「Audit logs & SIEM」菜单的 SIEM 子页可点击（`Feature.SIEM` 加入 `COMMUNITY_FEATURES`）→ 前端构建通过。

## Context
- 技术栈：NestJS + Kysely（`CamelCasePlugin`，表/列 snake_case，代码 camelCase）+ BullMQ + undici + Mantine/React Query 前端。
- 相关功能：审计日志（audit-logs，已完成，提供 `AUDIT_SERVICE` 写 `audit` 表）；SIEM 复用同一 `audit` 表作为数据源。
- 基础设施（已存在，可直接复用）：
  - `siem_destinations` 表（21 列：config JSON、secrets 加密串、cursor_* 游标、status/consecutiveFailures/lastDeliveredAt/lastError/lastErrorAt/nextAttemptAt/failingSince、version 乐观锁）。
  - `QueueName.SIEM_QUEUE`（已注册，`SIEM_DELIVER`/`SIEM_SWEEP` 任务名）。
  - `EncryptionService.encrypt/decrypt`（密钥加密）。
  - `OutboundAgentFactory.lease(url, tls?)` + `undici` request（SSRF 安全出站）。
  - `SIEM_TEST_THROTTLER` 节流（测试接口）。
- 约束：
  - 出站必须经由 `OutboundAgentFactory`（禁止裸 fetch 到用户 URL，防 SSRF）。
  - secrets 不允许明文出现在响应或日志。
  - 仅 owner 可管理目的地（与前端 `isOwner` + `useHasFeature(Feature.SIEM)` 一致）。

## Non-goals
- 不实现 SaaS 许可校验/计费（社区自托管放开）。
- 不做历史审计日志的全量回填（仅从启用目的地后的新事件开始流式；游标从首个事件开始）。
- 不改动前端页面（沿用现有 `ee/siem/*`）。
