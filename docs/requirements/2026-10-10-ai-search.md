# 需求：AI 驱动的语义搜索（pgvector）端到端可用

- 日期：2026-10-10
- 关联：本需求是 `ai-settings` 功能的延续。此前已解除 `Feature.AI` 门控，使「设置 → AI 设置」中的 AI 搜索开关可在自托管社区版开启；但开启时后端 `WorkspaceService.update` 报 `Failed to activate. Make sure pgvector postgres extension is installed.`，因为 `page_embeddings` 表与 pgvector 扩展从未被创建，且 embedding 生成/检索逻辑缺失。

## 背景与现状（只读探索确认）
- 触发侧已存在：`queue.constants.ts` 定义 `GENERATE_PAGE_EMBEDDINGS` / `DELETE_PAGE_EMBEDDINGS` / `WORKSPACE_CREATE_EMBEDDINGS` / `WORKSPACE_DELETE_EMBEDDINGS` / `WORKSPACE_RESET_EMBEDDINGS`；`workspace.service.ts` 在开启/关闭 `aiSearch` 时向 `AI_QUEUE` enqueue；`page.listener.ts` 在页面生命周期事件里也向 `AI_QUEUE` 投递 job。
- 消费侧缺失：**全仓库没有任何 `@Processor(QueueName.AI_QUEUE)` 处理器**，这些 job 无人消费。
- 存储层：`db.interface.ts` 已声明 `pageEmbeddings: PageEmbeddings`，但**没有建表迁移**，也没有 `PageEmbeddingsRepo`。
- 生成/检索：没有任何调用 embedding 模型的代码；`search.service.ts` 仅做 `tsvector` 全文检索，无向量分支。
- 前端：搜索 spotlight 已有 `isAiMode`（AI 模式），但 AI 模式走 `useAiSearch()` 调用 `/api/ai/answers`（服务端无对应 controller）；且 `handleSpotlightOpen` 仅在 `AI_VECTOR_DRIVER==='turbopuffer'` 时预热缓存，pgvector 路径无动作。
- 配置已就绪（无需新增）：`AI_EMBEDDING_MODEL` / `AI_EMBEDDING_DIMENSION` / `AI_VECTOR_DRIVER`（默认 `pgvector`）/`getAiEmbeddingModel()` / `getAiEmbeddingDimension()` / `getOpenAiApiKey()` / `getOpenAiApiUrl()` 均存在于 `environment.service.ts` 与 `environment.validation.ts`。

## 目标
让自托管社区版开启「AI 驱动的搜索」后，能够：
1. **开启开关不再报错**：`page_embeddings` 表与 `vector` 扩展由迁移创建，`WorkspaceService.update` 的表存在性检查通过。
2. **页面内容被自动向量化**：页面创建/更新/删除（以及开启开关时对存量页面）触发 embedding 生成/删除，写入 `page_embeddings`。
3. **搜索具备语义能力**：在现有 `POST /search` 中增加 pgvector 向量相似度分支（与全文 `ts_rank` 做 hybrid 融合），当 workspace 开启 `ai.search` 且 `AI_VECTOR_DRIVER==='pgvector'` 时，按语义相关性返回/重排结果。
4. **前端 AI 模式可用**：搜索 spotlight 的 AI 模式在 pgvector + `ai.search` 开启时，改为走语义 `/search`（复用 `useUnifiedSearch`），展示语义检索结果，而非调用不存在的 `/api/ai/answers`。

## 非目标（本次范围外）
- `turbopuffer` 向量驱动（保留既有占位逻辑，不实现其客户端）。
- 生成式问答（`/api/ai/answers` 的 LLM 流式回答生成）——属于 "Generative AI"，不在本次范围；本次只做语义「检索」，不做生成式答案。
- 附件（attachment）embedding：本次仅对页面 `text_content` 做 embedding；附件 embedding 留待后续。
- `gemini`/`ollama` 驱动的 embedding：本次 embedding 生成要求使用 OpenAI 兼容驱动（`AI_DRIVER=openai`/`openai-compatible`），并在文档/校验中说明；其他驱动的 embedding 分支留待后续。

## 验收标准
1. 新增迁移在 Postgres 中 `CREATE EXTENSION IF NOT EXISTS vector` 并创建 `page_embeddings` 表（含 `embedding vector(<dim>)` 列与 HNSW/ivfflat 索引）。`isPageEmbeddingsTableExists` 在建表后为 `true`。
2. 新增 `@Processor(QueueName.AI_QUEUE)` 处理器，正确消费 `GENERATE_PAGE_EMBEDDINGS` / `DELETE_PAGE_EMBEDDINGS` / `WORKSPACE_CREATE_EMBEDDINGS` / `WORKSPACE_DELETE_EMBEDDINGS` / `WORKSPACE_RESET_EMBEDDINGS`（及页面生命周期事件 job），调用 `EmbeddingService` 生成/删除 embedding。
3. `EmbeddingService.embed(texts)` 复用 AI driver（OpenAI 兼容）的 provider 构建逻辑，返回向量数组；配合文本分块工具对页面 `text_content` 分块。
4. 页面创建/更新/删除事件触发 embedding 生成/删除；开启 `aiSearch` 时对 workspace 下存量页面批量生成。
5. `search.service.searchPage` 在 `ai.search` 开启且 `pgvector` 驱动下，使用 `EmbeddingService.embed(query)` + `page_embeddings` 向量距离（`<=>`）做语义检索，并与全文 `ts_rank` 融合排序；结果仍走现有权限过滤与渲染。
6. 前端搜索 spotlight 的 AI 模式在 pgvector + `ai.search` 开启时走语义 `/search` 并返回语义结果，不再依赖不存在的 `/api/ai/answers`。
7. 编译通过（`server tsc` + `client build`），既有与新增测试全绿。

## 关键风险
- 迁移后需运行 kysely codegen 重建 `db.d.ts`，使 `page_embeddings` 进入类型；向量距离查询须用原生 `sql`（kysely 不识别 `<=>` 算子）。
- embedding 维度 `dim` 取自 `getAiEmbeddingDimension()`，建表 `vector(<dim>)` 必须与实际 embedding 维度一致；若维度配置变更需重建索引/重算 embedding（用 `WORKSPACE_RESET_EMBEDDINGS`）。
- `AI_EMBEDDING_MODEL` / `AI_EMBEDDING_DIMENSION` 在 pgvector 路径下应视为必填；需在 `environment.validation.ts` 增加 `@ValidateIf(AI_VECTOR_DRIVER==='pgvector')` 必填校验。
- 真实 embedding 调用需要可用的 LLM embedding 端点与 API key（运行环境配置），单测中以 mock 覆盖。
