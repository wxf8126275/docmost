# AI Chat (独立实现)

## Problem
Docmost 企业版的 AI 对话前端存在于 `apps/client/src/ee/ai-chat`，但其后端
（controller / service / repo / 流式发送）不在本仓库中（`apps/server/src/ee` 为空）。
我们以**独立、干净的实现**在核心代码中补齐 AI 对话能力，使其无需企业版许可即可使用。
代码全部放在 `apps/server/src/core/ai-chat` 与 `apps/client/src/features/ai-chat`，
不复制、不修改 `ee/` 下任何代码，也不改动许可/授权判定逻辑。

## Behaviors
- 已认证用户可在自己 workspace 内创建、列出、打开、重命名、删除、搜索 AI 对话。
- 用户发送消息后，以 SSE 流式接收助手回复（事件：`chat_created` / `content` / `done` / `error`）。
- 对话与消息持久化（表 `ai_chats`、`ai_chat_messages` 已由核心迁移定义）。
- 助手由**可配置的 OpenAI 兼容大模型**驱动（env：`AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`；
  复用已依赖的 Vercel AI SDK `ai` + `@ai-sdk/openai`）。
- （可选/后续）页面上下文：将 `@提及` 的页面内容作为对话上下文带入。

## Acceptance Criteria
- `POST /api/ai/chats/create` 返回新建 chat 的 id → verifiable by test
- `POST /api/ai/chats` 分页列出当前用户的对话 → verifiable by test
- `POST /api/ai/chats/info` 返回 chat + 消息列表 → verifiable by test
- `POST /api/ai/chats/update` 重命名 → verifiable by test
- `POST /api/ai/chats/delete` 软删除 → verifiable by test
- `POST /api/ai/chats/search` 按文本搜索 → verifiable by test
- `POST /api/ai/chats/send` 流式返回 SSE 事件（chat_created / content / done / error）→ verifiable by test
- 前端页面可发起对话、查看历史、管理对话 → verifiable by demo
- 测试：service 单测（mock LLM 流）、controller/e2e 至少一条 send 流程 → verifiable by test

## Context
- 技术栈：NestJS 11 (Fastify)、Kysely/Postgres、React 19、React Query、Vercel AI SDK。
- DB 表 `ai_chats` / `ai_chat_messages` 已迁移（`20260409T132415-ai-chat.ts`）；
  `db.d.ts` 尚未包含这两张表的类型，实现时需手动补齐（遵循现有模式）。
- 路由全局前缀 `/api`；`/api` 路径要求已认证 workspace 上下文（`workspaceId` / `userId`）。
- 约束：不得修改 `ee/` 代码或许可门控；遵循 `docs/team/conventions.md`。

## Non-goals
- 工具调用 / agentic RAG（MVP 外，可后续扩展）。
- 对话附件上传（可复用现有 attachment service，MVP 不实现）。
- 计费 / 配额限制。
