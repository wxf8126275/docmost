## 上下文要点（已探索确认）
- 触发侧已就绪：`queue.constants.ts` 定义 `GENERATE_PAGE_EMBEDDINGS` / `DELETE_PAGE_EMBEDDINGS` / `WORKSPACE_CREATE_EMBEDDINGS` / `WORKSPACE_DELETE_EMBEDDINGS` / `WORKSPACE_RESET_EMBEDDINGS`；`workspace.service.ts` 在开启/关闭 `aiSearch` 时向 `AI_QUEUE` enqueue；`page.listener.ts` 在 `PAGE_CREATED/DELETED/SOFT_DELETED/RESTORED` 事件里向 `AI_QUEUE` 投递（但 `PAGE_UPDATED` 仅投 `SEARCH_QUEUE`，需补）。
- 消费侧缺失：无 `@Processor(QueueName.AI_QUEUE)`，无 `page_embeddings` 迁移/表，无 `PageEmbeddingsRepo`，无 embedding 生成/检索代码。
- `db.interface.ts` 已手工声明 `pageEmbeddings: PageEmbeddings`，因此 TS 侧类型已存在，无需 codegen 即可编译；运行时表由迁移创建。
- `AiChatLlmClient.buildModel` 用 `createOpenAI({apiKey, baseURL})` 装配 OpenAI 兼容 provider，可被 embedding 复用（用 `openai.embedding(model)` + `embedMany`）。
- 配置已存在：`AI_EMBEDDING_MODEL` / `AI_EMBEDDING_DIMENSION` / `AI_VECTOR_DRIVER`（默认 `pgvector`）/ `getAiEmbeddingModel()` / `getAiEmbeddingDimension()` / `getOpenAiApiKey()` / `getOpenAiApiUrl()`。

## 风险与对策
- `embedding vector` 不设维度：避免与 `AI_EMBEDDING_DIMENSION` 配置耦合；运行时插入向量长度须与 provider 实际维度一致（由 provider 决定），若不一致 pgvector 报错——已在 `AI_VECTOR_DRIVER==='pgvector'` 下强制 `AI_EMBEDDING_MODEL`/`AI_EMBEDDING_DIMENSION` 必填以约束一致性。
- 真实 embedding 调用需可用 LLM embedding 端点 + key（运行环境配置），单测以 mock 覆盖；本地 e2e 需配置。
- 向量距离查询必须用原生 `sql`（`<=>` 算子 kysely 不识别）。
- 仅 OpenAI 兼容驱动做 embedding（gemini/ollama 的 embedding 留待后续）。
